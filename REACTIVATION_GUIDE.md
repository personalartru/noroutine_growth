# Реактивация подписчиков MAX-канала

## Что это

Автоматическая система для возвращения неактивных подписчиков канала через персональные сообщения.

## Как работает

### Этап 1: Публикация поста с кнопкой "Я тут!"

**Что происходит:**
- Раз в 2 недели (воскресенье, 13:00 МСК) в канал публикуется пост с кнопкой "Я тут! 👋"
- Подписчики, которые нажимают кнопку, помечаются как активные
- Их `user_id` сохраняется в `.max_active_users.json`

**Ручной запуск:**
```bash
# Локально (с токенами в .env)
python3 reactivate_subscribers.py publish

# Или через GitHub Actions
gh workflow run reactivate-subscribers.yml --repo personalartru/noroutine_growth -f action=publish
```

### Этап 2: Отправка сообщений неактивным (через 3 дня)

**Что происходит:**
- Через 3 дня после публикации поста запускается скрипт `reactivate`
- Получает список всех подписчиков канала
- Фильтрует тех, кто **НЕ нажал** кнопку "Я тут!" за последние 14 дней
- Отправляет каждому личное сообщение с вопросом о контенте

**Ручной запуск:**
```bash
# Локально
python3 reactivate_subscribers.py reactivate

# Или через GitHub Actions
gh workflow run reactivate-subscribers.yml --repo personalartru/noroutine_growth -f action=reactivate
```

## Текст сообщения реактивации

```
Привет, {Имя}! 👋

Заметил, что вы давно не взаимодействовали с постами в канале.
Мне важно знать, интересен ли вам контент.

Напишите, пожалуйста:
• Что бы вы хотели видеть в канале?
• Какие темы для вас актуальны?
• Или просто напишите 'Всё ок', если контент подходит 🙂

Спасибо за ваше время!
```

## Ограничения

1. **Требуется диалог с ботом:** сообщение можно отправить только тем подписчикам, которые хотя бы раз запускали бота (их `chat_id` известен из `.max_dialogs.json`).
2. **MAX API не предоставляет `last_activity_time` для подписчиков канала** → используем кнопку "Я тут!" как индикатор активности.
3. **Rate limiting:** между сообщениями задержка 1 сек (можно отправить ~3600 сообщений/час).

## Файлы и кеш

- `.max_active_users.json` — user_id тех, кто нажал "Я тут!" (timestamp последнего нажатия)
- `.max_dialogs.json` — соответствие user_id → chat_id диалога (для отправки личных сообщений)
- Оба файла хранятся в GitHub Actions Cache (key: `reactivate-cache-*`)

## Мониторинг

После завершения реактивации в админский чат (если `MAX_ADMIN_CHAT_ID` установлен) приходит сообщение:

```
✅ Реактивация завершена

Отправлено: 42
Пропущено: 158
```

## Настройка GitHub Actions

### Секреты (уже установлены)

- `MAX_BOT_TOKEN` — токен бота MAX
- `MAX_CHANNEL_ID` — ID канала (по умолчанию `-71062363105923`)
- `MAX_ADMIN_CHAT_ID` — ID чата для уведомлений

### Расписание

По умолчанию:
- **Публикация поста:** каждые 2 недели, воскресенье 10:00 UTC (13:00 МСК)
- **Отправка сообщений:** вручную через 3 дня после публикации

Можно автоматизировать: изменить `reactivate-subscribers.yml` для автоматического запуска `reactivate` через 3 дня после `publish` (добавить второй schedule или использовать `workflow_run`).

## Ожидаемый эффект

- **10-15%** неактивных подписчиков ответят на сообщение
- **5-10%** вернутся к чтению постов
- **2-5%** отпишутся (это нормально — очистка от незаинтересованных)

## Следующие шаги

1. ✅ Протестируйте публикацию поста: `gh workflow run reactivate-subscribers.yml -f action=publish`
2. Через 3 дня проверьте `.max_active_users.json` (кто нажал кнопку)
3. Запустите реактивацию: `gh workflow run reactivate-subscribers.yml -f action=reactivate`
4. Проанализируйте ответы подписчиков и адаптируйте контент
